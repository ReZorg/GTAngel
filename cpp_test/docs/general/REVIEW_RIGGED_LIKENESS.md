# DTE guard preview → rigged likeness: native GTAngel review

**Scope:** GTAngel v21 native-renderer guard/folded frames and the supplied DTE motion guide and reference images. This is an assessment and implementation plan, **not** an assertion that a rig or photoreal asset has been made. I did not reopen the user-attached images; character and scene comparisons below draw on the references already visible in the conversation and the guide's explicit identity/pose specifications. The generated frames reviewed here are [`v21_dte_guard_close.png`](v21_dte_guard_close.png) and [`v21_dte_folded_close.png`](v21_dte_folded_close.png).

## Diagnosis in one sentence

The two shoulder-mounted wings and visual-only control boundary are sound, but the prototype is **a small, untextured stick-and-tube figure in a flat, unlit arena**; a rigged mesh, meaningful art-direction geometry, suitable camera, and materially different renderer are all needed to match the reference character.

**Important distinction:** The current `ObjectAvatar` expansion of about **52.1%** between folded and guard verifies wing deployment in the semantic framebuffer. It does **not** indicate facial fidelity, correct skinning, material realism, foot locking or rig readiness.

## Recommended asset and runtime contract

1. **Create the art asset, not a traced image projection.** Request/author a neutral multi-view turnaround and A/T-pose sheet, then create the original DTE mesh in Blender or equivalent. The supplied boards are directional visual references. The guide mentions T-pose/A-pose/turnaround, wing weights and material-spec files under `/home/ubuntu/echo-angel-video/`; these **five specified files are absent in this execution environment**. Obtain or recreate them before approving proportions and wing geometry. Record asset rights and derivation.
2. **Use a portable skeletal interchange.** A `.glb`/glTF 2.0 export can carry named joints, `JOINTS_0`/`WEIGHTS_0`, inverse-bind matrices, indexed geometry and texture/material slots; the game must **implement/choose a validated loader**, since v21 cannot import it today. Current pose values should map into local bone transforms; world transform continues to come only from the locally governed v20 body. [Khronos's skinning tutorial](https://github.khronos.org/glTF-Tutorials/gltfTutorial/gltfTutorial_020_Skins.html) specifies the joint/weight/inverse-bind relationship. Paint-test shoulder, elbow, hip, skirt, hand and wing mounts rather than relying solely on automatic weights; [Blender warns](https://docs.blender.org/manual/en/latest/animation/armatures/skinning/parenting.html) that automatic armature weights can deform complex overlaps incorrectly.
3. **Divide deformation responsibility.** Skinned body/top/hands, discrete harness and plate transforms attached rigidly to wing bones, weighted/simulated hair, skort and ribbons with fallback keyed motion. Do **not** weight the harness to the head; do **not** allow simulated ribbons to drag the boom. Provide `wing_mount_l/r`, `wing_tip_l/r`, `hand_cast`, `foot_l/r` sockets, `WingDeploy`, `WingEnergyPhase` and per-side pitch/spread controls. Animation events are descriptive, not world/motor commits.
4. **Provide LOD and renderer budget measured on hardware.** A few-thousand-triangle skinned asset may be a useful *test*, not a guaranteed photoreal target; choose actual mesh/texture/LOD budgets from measured Windows third-person performance. The existing 768² **software** benchmark was around **25–30 ms/frame** in v21 before a dense skinned mesh and advanced shading; there is little headroom for a high-fidelity software raster pass. [Epic's LOD documentation](https://dev.epicgames.com/documentation/en-us/unreal-engine/skeletal-mesh-lods-in-unreal-engine) describes preserving significant bones/mesh edges while reducing distant mesh cost (guidance, not a dependency on Unreal).
5. **Recommended renderer route: optional D3D11 Win32 path**, with a supported CPU fallback for tests. Render 768×768 colour, depth and integer object-ID targets from **the same posed geometry and camera**; derive the existing 64×64 and 12×12 cognitive views from the *actual* authoritative colour/depth/ID output. Use coherent frame sequence stamps and bounded readback; if readback is stale/missing, local actuation/world governance fail closed. Preserve the v20 `SpinalReflex` and `WorldGovernance` commit gates, the Ariadne quest, collision and versioned saves. A more capable PBR renderer is required to display glTF's [metallic–roughness/normal/emissive materials](https://www.khronos.org/gltf/pbr/); merely loading glTF in the current flat-colour rasterizer will still look flat.

| **C — in-engine skinning and animation** | Asset validation/import, bone palette/skin pass, 24-frame walk, 36-frame entry, stop/recovery/idle, IK and event sockets. | F0/F24 loop tangents agree; foot contacts do not skate in world coordinates over the held phase; 17–23 deployment preserves root→tip plate order; hand orb tracks the **front casting hand**; movement/world states stay unchanged when only animation advances. |
| **D — fidelity renderer and city** | PBR-capable optional GPU renderer, quality LODs, wet-neon diorama and bounded VFX. | Native Windows capture shows matching palette, outfit, face and two-wing crystal silhouette under front/¾/rear views; measured gameplay and rendering budgets pass chosen hardware targets; 768² colour/depth/ID remain mutually aligned on a frame stamp. |
| **E — embodied safety/regression** | Exact 3-buffer capture and end-to-end quest playthrough on workstation. | v20's 124 CNS checks, Ariadne's 17 checks and beacon semantic re-observation remain green; no proposal source bypasses motor/niche reflexes; local camera and collision stay authoritative; visuals are accepted via **actual native GUI screenshot/video**, not a generated reference image. |

**Practical judgment:** A first **recognizable** rigged DTE is feasible as a bounded, native Win32 asset/rendering project. A **photoreal, reference-matched** DTE is not a texture swap or a few more `addTriangle` calls: it needs an authored mesh/rig and a substantially more capable material/lighting path. DAEDALOS can catalog asset provenance/device revisions and Agent Zero can propose narrative/attention, but neither gains body or world-effect authority. The most impressive demonstration would be a face-readable DTE approaching Ariadne, wings unfolding with mechanically tracked plates and cyan hand light, repairing the beacon under WGR, then seeing the same change in her own exact 768² colour/depth/ID field while the scene's wet neon reflects it.

## Addendum — what `/Deep Tree Echo` examples contribute

The user-supplied `/Deep Tree Echo` skill is more than a prose identity note: its directory also contains `EchoCognitive.h/.cpp`, `EchoPed.h/.cpp`, `EchoOrchestra.h/.cpp`, a cognitive test, and legacy `Ped`, `World`, `Weapon`, `Vehicle`, and `glfw` files. These were **read as design references only**. The latter depend on RenderWare/game-engine classes and are neither portable GTAngel rig assets nor safe code to splice into the clean-room Win32 app. `EchoPed` does **not** provide an artist-authored mesh, skin weights, animation clips, face blendshapes, or two-wing model. The T/A-pose and material assets named by the separate style guide are still absent here.

**Suggested bounded contract:** `MeasuredFrame{seq, colour/depth/id evidence, body, worldVersion, questOutcome}` → `EchoObservation` (local normalized, finite, provenance-tagged) → `ExpressionIntent{identityId, frameSeq, ttl, AU[1,4,6,12,26], gaze, posture, wingAffect, confidence}` → `ExpressionGovernor` (finite/range/expiry/identity checks, player/NPC ownership and 2-wing/quiet-state constraints) → **rig pose/material sockets only**. World, body, collision and quest are *not* writable outputs of this interface. Agent Zero may suggest a narrative focus or salient memory; DAEDALOS registers schema/provenance and observes violations; the local reflexes retain exclusive effectors.

**Authenticity criterion:** The cognitive examples implement a live numerical state machine but **not** an LLM-generated conversation: `EchoMind_ReasoningPrompt` formats a short local request while `CompleteReasoning` clears it and increases confidence without actually invoking a reasoning model (`EchoCognitive.cpp` lines 524–546). It would be inaccurate to call that dynamic dialogue or deep reasoning. A future speaking Echo should generate context- and role-conditioned responses from an actual configured model, ground them in verified quest/memory state, log imperfections/errors, and leave Ariadne's deterministic v19 quest fixture intact unless a separately verified dialogue layer is explicitly introduced.

**New acceptance gate after rigging:** For two *different* real local observation sequences with the same mesh and no `B` key, expression packets should differ appropriately in AU/gaze/posture yet never alter the authoritative body transform/speed, world version, NPC collision, quest stage, or saved identity without a valid local authority path. For a replay of the *same* authenticated observation sequence, output should be traceable and reproducible up to bounded cosmetic noise. A lost/stale cognitive source must fade its own overlay to neutral and leave an explicitly held operator pose (including `B` guard) untouched—not substitute synthetic perception or a fabricated reaction.
